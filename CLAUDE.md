# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is **Ressam**, a tabletop RPG (TTRPG) rulebook written in Markdown. The repository is content/rules-authoring - edits to game design text, tables, and formulas, not software. Every file under `core/` is plain hand-authored Markdown, edited directly - there is no build step or generated content anymore. (A prior version of this repo rendered the weapons/armor tables, spell lists, feat lists, and progression table from structured YAML via a Python + Jinja2 pipeline; that pipeline was removed once prototyping wrapped up, and its output was kept in place as ordinary Markdown.)

## Repository structure

- `core/core_rules.md` - foundational resolution mechanics: dice, attributes, skills, checks vs. Ward, Basic Moves (Dashing, Disengaging, Shoving, Disarming, Close the Gap, Blind, Grappling, Defensive Stance, Feint, Taunting - the proactive, on-your-turn actions everyone has access to). Read this first; nearly every other chapter assumes these definitions. Three sibling chapters below split off what used to live here once the single file grew too dense: `wounds_and_survival.md`, `carrying_and_resting.md`, and `exploration/stealth_and_light.md`.
- `core/wounds_and_survival.md` - Damage Types (Physical/Elemental/Occult, Resistance/Vulnerability/Immunity), Wounds and Survival (Wound Penalty, Dying, Coup de Grace, Stabilization, Scars, Falling, Food and Water, Suffocation, Patched Wounds, Wound Recovery), and Trauma - the "what happens when things go wrong" cluster, split out of `core_rules.md`.
- `core/carrying_and_resting.md` - Slots (carrying capacity, Size modifiers, Slot Costs) and Resting (Short/Field/Long Rest ladder) - the logistics cluster, split out of `core_rules.md`.
- `core/character/` - building and advancing a character: `character_creation.md` (step-by-step guide), `attributes_and_skills.md` (reference glossary: what each of the 8 Attributes represents and what each Skill covers, grouped by category - the mechanics that use these numbers, like the Skill Check formula and DC tiers, stay in `core_rules.md` and are linked from here rather than duplicated), `races/` (one hand-authored file per race, indexed by `races_overview.md` - see below), `careers.md`, `languages.md`, `progression_&_rewards.md` (the per-level advancement table, plus static prose covering Rewards & Treasure and Itemization).
  - `core/character/races/` - `races_overview.md` (hand-authored: General Rules Notes, Level Adjustment, and an index of races grouped by Artefolk/Cursed/Mystik/Night-Terror) plus one hand-authored file per race (`aelves.md`, `dwergaz.md`, `humans.md`, `orkhs.md`, `alsahli.md`, `feliids.md`, `skeggs.md`, `tembels.md`, `khoridae.md`, `dzinari.md`, `golems.md`, `tapio.md`, `daemons.md`, `varulf.md`, `strygs.md`). This split (one page per race, mirroring `core/magic/arcane/` and `core/magic/divine/`) exists to make individual races easier to manage and to leave room for per-race lore.
- `core/combat/` - `combat.md` (turn structure, action economy, attack/damage rolls, critical hits, and Mythic Initiative - campaign-boss creatures rolling initiative X times and taking a full turn on each count, at an escalating penalty, instead of one turn per round) and `maneuvers.md` (the reactive Reaction options answering an incoming attack, reworked 2026-08-09 per `hema-combat-design.md`'s compression model: Oppose - a single `1d12 + Weapon Skill, Shields Skill, or DEX` roll, whichever funds it, resolved off a shared Margin table, unlocking a four-item Effect menu (Strike, Shift, Control, Recover) on a won exchange instead of three separate named rolls (the old Parry/Block/Dodge) each with their own Effect list - the Press, a generalized reaction chain letting either side of a contest (winner or loser) spend another Reaction to re-roll instead of accepting a result - and Reactive Casting, the caster's alternative to Oppose, unchanged). Reach collapsed the same pass: four Reach Categories (Short/Medium/Long/Very Long) became three Measure Bands (Grip/Near/Far, see `weapons.md`), compared symmetrically per-combatant rather than as a fixed longer/shorter pairing. The proactive, on-your-turn moves that used to live here (Dashing, Shoving, Grappling, etc.) now live in core_rules.md's Basic Moves section, alongside the new Shift Measure Minor Action that replaced the old Close the Gap Basic Move - maneuvers.md is exclusively the reactive exchange. Bestiary stat blocks (`core/bestiary/`) still reference the pre-rework Parry/Block/Dodge system as of this rework - see `TODO.md`. The simulation tooling (`tools/*.py`) has since been rewritten against Oppose - see the `tools/` bullet below.
- `core/magic/` - spellcasting rules split into `laws_of_magic.md` (the in-fiction physics every spell, ritual, and minor working answers to - Five Laws that bound what magic can ever do (no true creation from nothing, no touching past/future, no making/unmaking/growing a soul, no rewriting essential nature by mortal craft, no effect without a thread of sight/touch/sympathy), Three Costs that price what's lawful but costly (Conservation, Signature, Reciprocity), and an Adjudication section for when the spell lists are silent on a player's novel idea - read this before ruling on anything not covered by an existing spell), `magic_overview.md` (universal rules shared by both paths), `minor_magic.md` (small, instinctive Mana effects - minimum 1 Mana, scaling in scale/duration from there - that fall outside a normal spell), and `spell_crafting.md`, with two parallel school trees:
  - `magic/arcane/` - arcane schools (aeromancy, geomancy, hydromancy, pyromancy, shadowmancy) plus `arcane_overview.md`.
  - `magic/divine/` - divine schools (benediction, cultivation, invocation, necration, subjugation) plus `divine_overview.md`.
- `core/feats/` - feat categories (general, martial, arcane, divine, prestige, skill), indexed by `feats_overview.md`.
- `core/equipment/` - `armor.md`, `weapons.md`, `supplies.md`, and `alchemy.md` (crafting oils/bombs/salves from ingredients).
- `core/exploration/` - travel and downtime layer: `traveling.md` (hex travel, mounts), `downtime.md` (revelry/celebrations), `leadership.md` (followers and cohorts), `dungeon_turns.md` (the 10-minute Turn as the clock for dungeon/site exploration - light tracking and wandering encounters share one party-wide tally), and `stealth_and_light.md` (Stealth and Hiding, Light and Vision - split out of `core_rules.md` and placed here since Light and Vision's burn-duration table already lived in lockstep with `dungeon_turns.md`'s Light Tracker). These feed the core loop directly, not optional flavor: Traveling is how the party reaches a dungeon and burns rations, Leadership is how a growing operation delves deeper without resurfacing, and Downtime is where rewards from delving cycle back into progression.
- `core/setting/` - the world of Ressam itself: `setting_overview.md` (welcome blurb, currency, language, and an index of this chapter - the `races_overview.md`/`feats_overview.md` pattern), `calendar.md` (the seasonal year and its festivals), `history.md` (Age of Mythos, the Sundering, Age of Revival, and the Third Age's wars up to 402 RC), `geography.md` (the Mourning Star and twin moons, the continents, and the Mortal Plane/Fields of Nocturne), `nations.md` (the great powers, the nation relations table, and global/local factions), `religions.md` (the faiths practiced across Ressam), and `heroes.md` (legendary figures). Cross-references a lot with `core/character/races/` - each race's own page covers that race's culture and mythology in more depth than fits here.
- `DESIGN_GUIDE.md` - the yardstick for evaluating any mechanic, item, spell, or rule change: five Design Pillars (Realism as "feel, don't simulate," Elegance, Scarcity, Niches, and Distinction between Martials and Casters), followed by Spell Design Guidelines covering damage caps (`Xd8 x Mana`, Pyromancy alone at `Xd10 x Mana`), the no-save-or-suck rule for Overcome spells, summoning being near-exclusive to Necromancy, per-school distinctiveness, Faith always being required for divine magic, healing defaulting to Patched Wounds, spells not bypassing mechanics for free, and Gish/spellblade playstyles being a Feat-driven compromise rather than something magic grants directly. Read this before proposing or reviewing changes to `core/magic/`, `core/feats/`, or `core/equipment/` - it's the reasoning behind *why* those files are shaped the way they are, not just what's in them. Several of its Spell Design Guidelines (Creation, Healing, Summoning, Faith, Bypass) are the mechanical/production-side expression of Laws `laws_of_magic.md` states in-fiction (Borrowed Substance, Conservation, the Soul, Reciprocity) - the two files should stay consistent with each other when either changes.
- `tools/` - Python, standalone (stdlib only, no install step) - the computational counterpart to `DESIGN_GUIDE.md`'s qualitative pillars: run these to check whether a mechanical change actually lands the way it reads on paper, rather than eyeballing it. Two independent pieces:
  - `power_score.py` - prices a creature backward through `progression_&_rewards.md`'s own Attribute/Skill/Feat advancement table to find the lowest PC Level that could legally afford it (its "Effective Level"), and reads an XP reward straight off that table - no borrowed CR-style curve, no simulation, just point-budget accounting. Cheap enough to run on every bestiary entry.
  - `combat_engine.py` (a standalone Oppose/Effect/Press resolution engine - dice, Attack Roll vs. Evasion, Margin table, Shield Guard, the Strike/Shift/Control/Recover Effect menu, Press chains, Mythic Initiative - matching `core/combat/maneuvers.md` and `combat.md` as of the 2026-08-09 rework) backs two Monte Carlo rating tools, `creature_rating.py` (1-on-1) and `encounter_rating.py` (N monsters vs. a 4-PC party). **Why this shape, not a raw number or a D\&D-style CR curve:** Ressam PCs don't scale much across Level 1-12 (progression_&_rewards.md's Attribute-point budget only moves from 18 to 21 over the whole ladder), so both tools instead simulate many fights against one fixed reference build, `combat_engine.BASELINE_PC`, and bucket the win rate into a 5-tier rating - **Much Worse / Worse / Equal / Better / Much Better** - that stays meaningful at any Level rather than needing a level-scaled baseline. Run them (`python3 tools/creature_rating.py`, `python3 tools/encounter_rating.py`) after any change to `core/combat/`, `core/equipment/weapons.md` or `armor.md`, or a creature's Attributes/Skills/gear, to see whether the change actually shifted the tier you meant it to. The `bestiary-npc` skill (`.claude/skills/`) already wires both into its Validate stage when generating `core/bestiary/*.md` entries.
- `CREDITS.md` - attribution and licensing note.
- `TODO.md` - planning doc for in-progress, cross-session rework items, when one exists. Only exists while something is actively open; gets deleted once that item is fully resolved and merged, so its absence means "nothing outstanding" rather than an oversight. Check it (and recent git log/diff) before touching feats, combat, or equipment mechanics - a change already in flight may be scoped and reasoned here.
- `assets/` - currently empty (reserved for future images/handouts).
- `templates/character/character_sheet.html` - a hand-authored, self-contained interactive player character sheet (plain HTML/CSS/JS, no build step, no dependency on anything else in the repo) - a player fills in race/career/feats/spells/equipment by hand. Open it directly in a browser to use it.
- `templates/Home.md` and `templates/_Sidebar.md` - local reference copies of the two GitHub Wiki pages that are hand-edited directly in the wiki UI (see "Publishing: GitHub Wiki" below); kept here for convenience when drafting changes before pasting them into the wiki.
- `.github/workflows/sync-wiki.yml` - CI that publishes `core/` to the GitHub Wiki; see "Publishing: GitHub Wiki" below.
- `README.md` - short public-facing entry point (project blurb + link to the GitHub Wiki).

## Publishing: GitHub Wiki

The rulebook is published as a GitHub Wiki, auto-synced from `core/` on every push to `main` via `.github/workflows/sync-wiki.yml`: the workflow clones the wiki's own git repo (`<repo>.wiki.git`), mirrors `core/`'s contents into it 1:1 (folder structure preserved, `core/` prefix stripped), and pushes only if something changed. **Never hand-edit wiki pages that correspond to a `core/**/*.md` file** - edits made directly in the wiki UI are silently overwritten on the next sync. Edit `core/` and let CI publish it.

Two pages exist **only** in the wiki repo, not in this one, and *are* meant to be hand-edited directly in the wiki UI: `Home.md` (landing page) and `_Sidebar.md` (persistent nav, shown on every page). The sync workflow explicitly excludes both from its mirror/delete step so it never overwrites them. Both list every chapter grouped by section, in the same order as "Repository structure" above. Local reference copies live at `templates/Home.md` and `templates/_Sidebar.md` for convenience - edit those first, then paste the result into the wiki UI. When a chapter is added, renamed, or removed under `core/`, update both pages (and their local copies) to match.

**GitHub Wiki quirk to know before editing either page:** wiki page URLs/links are flat and basename-only, regardless of which subfolder a file is mirrored into - e.g. `core/magic/arcane/pyromancy.md` is mirrored to `magic/arcane/pyromancy.md` in the wiki repo but renders at `/wiki/pyromancy`, not `/wiki/magic/arcane/pyromancy`. Multi-level nested paths in Markdown links (e.g. `[Pyromancy](magic/arcane/pyromancy)`) 404. Always link to wiki pages by bare filename with no folder prefix and no `.md` extension, e.g. `[Pyromancy](pyromancy)`. This only works because every `core/**/*.md` basename is unique repo-wide - if that ever stops being true, this linking scheme needs to be revisited.

## Content conventions

- Em Dashes (—) and En Dashes (–) are not used, instead use only Hyphens (-).
- Files are exported from Google Docs, so literal Markdown-special characters are backslash-escaped in the source (e.g. `1d12 \+ Skill Ranks \+ Attribute`, `Ressam is not Dungeons \& Dragons`, `Slots \= STR \+ END`). Preserve this escaping style when editing existing text so re-exports/diffs stay clean.
- Formulas and derived stats are given as bolded inline math (e.g. `**Maximum Wounds = Size baseline + Feats**`) rather than code blocks. Follow this pattern for new formulas.
- Section breaks use a horizontal rule (`---`) between major topics within a chapter.
- Tables are used heavily for skill lists, DC tiers, and comparative mechanics (e.g. Arcane vs. Divine casting) - match existing table shapes when adding related content instead of introducing prose where a table already exists for that topic.
- Core terminology is reused verbatim across chapters (e.g. `Major Action`, `Ward`, `Evasion`, `AR`, `Trauma`, `Mana Cost`) - when editing one chapter, check whether the same term/mechanic is defined or referenced elsewhere (`core_rules.md`, `wounds_and_survival.md`, `combat.md`, `magic_overview.md`) so definitions stay consistent.
- The game's tone/scope per `core_rules.md`'s foreword: Ressam is a crunchy, lethal alternative to other TTRPGs, set in a world balanced around an early-1500s baseline - matchlock firearms sit alongside plate armor, magic is feared and regulated. Combat is the heart of the game; everything outside of it is meant to be played loosely, "rulings not rules."
